# July 2026 submission and judging checklist

This checklist maps FINITE to the published [challenge page](https://aibuilderschallenge-bob.bemyapp.com/)
and [official rules](https://res.cloudinary.com/ideation/image/upload/q_100%2Cf_pdf%2Cdpr_auto/id-ibm-skillsbuil-3eec69/pkqvg8j3q3a4teedy1kd.pdf).
The July entry is due **July 31, 2026 at 11:59 PM ET**. The selected theme is the
**Wildcard Challenge: Build Intelligent Systems for the Future of Work**.

## Non-negotiable eligibility and submission gates

- [ ] Entrant is at least 18 and currently enrolled at an eligible higher-education institution.
- [ ] Every team member is registered on the event platform and accepts the official rules.
- [ ] Team has one to five members; no member belongs to another team or July submission.
- [ ] Required IBM SkillsBuild activity is complete and evidence is retained.
- [ ] IBM Bob is a core development component, supported by genuine session evidence.
- [x] A functioning local proof of concept exists.
- [ ] A judge-accessible deployment or deterministic demo fallback is available.
- [ ] The GitHub repository is public and its exact submitted commit is tagged.
- [ ] README clearly states the problem, solution, technical approach and architecture,
  selected theme, real-world importance, and how IBM Bob was used.
- [ ] Project page includes project and team details plus the public GitHub URL.
- [ ] Public presentation video is no longer than three minutes.
- [ ] Submission is written in English and published before the deadline.
- [ ] Every asset is original or appropriately licensed; third-party rights are documented.

Items involving identity, enrollment, registration, coursework, Bob access, or account-level
publication must be completed by the entrant. They cannot be inferred from repository state.

## Twenty-point judging strategy

The rules describe four criteria scored from 1 to 5, for a maximum of 20 points.

| Criterion | Judge-visible FINITE evidence | Gate for a credible 5/5 |
|---|---|---|
| Technical Execution | Constraint contracts, conservative admission, durable executor, effect outbox, evidence digests, tests, MCP, and console | One repeatable command; green Python and console gates; genuine Bob calls; no unqualified claims |
| Innovation | Treat time, provider capacity, token/cost/context budgets, reliability, and effects as one execution envelope | Show a plan changing while mandatory promises remain fixed; explain why this is complementary to graph frameworks |
| Challenge Fit | Framework-neutral control plane for business-process and AI-workflow orchestration | Bob invokes FINITE through MCP on a Future-of-Work workflow and receives an actionable refusal or schedule witness |
| Implementation & Feasibility | SQLite restart ledger, bounded fixture executor, typed fictional StormShift workload, private console, watsonx seam | Clearly separate implemented behavior, deterministic simulation, live evidence, and post-hackathon work |

The public challenge page also highlights real-world impact, and the cross-challenge Grand Prize
explicitly considers impact. The demo therefore uses fictional emergency-operations coordination to
make the value of deadline, accessibility, bilingual, grounding, and effect-safety promises legible in
under three minutes. It must never imply deployment by Miami-Dade County or any external agency.

## Submission freeze sequence

1. Capture at least one substantive Bob planning/coding/testing session and Bob-to-FINITE MCP call.
2. Add a real Granite/watsonx receipt or explicitly omit the live claim if credentials are unavailable.
3. Freeze benchmark protocol, raw records, aggregation code, exact commit, and claim table.
4. Run all Python, MCP protocol, console render, dependency-audit, and reproducibility gates.
5. Publish the repository; verify it from an unauthenticated browser.
6. Record the three-minute proof sequence against the tagged commit and publish the video.
7. Complete the project page and re-check every external URL in a signed-out browser.
8. Submit early enough to recover from upload, account, or platform failures.
