# FINITE capability acceptance audit

Audit date: 2026-07-20. This audit scores the acceptance gates in `PROGRAM.md` against
executable repository code and tests. Roadmap prose, README claims, and the presence of a
console label are not treated as implementation evidence. A status of **Implemented** means
the stated gate has direct code and test evidence within its declared local/simulation scope;
**Partial** means some gate behavior exists but at least one material clause is unproved; and
**Not started** means there is no implementation of the gate itself.

Verification snapshot: all **199 collected tests passed** on the audited worktree with
**90.12% statement coverage**; this confirms the cited local tests run, but it does not substitute for
any missing live-provider, Bob, distributed-system, or statistical acceptance evidence.

## Executive summary

| Status | Must-win | Stretch | Total |

| Implemented | 10 | 0 | 10 |
| Partial | 22 | 6 | 28 |

| **Total audited** | **37** | **23** | **60** |

The strongest accepted slice is strict cross-format workflow compilation, conservative
admission, protected mandatory headroom, 10,000-transition resource conservation, bounded
context packing, effect-intent isolation, exact-scope approval, and the simulated transactional
effect outbox. The repository has substantial partial implementations around
durable execution, experiments, StormShift, and Bob-facing MCP, but those are not release
proof yet: the executor is fixture-only, the fault laboratory is pre-dispatch simulation, the
StormShift validator is intentionally structural, and the Bob build log contains no real Bob
session evidence.
