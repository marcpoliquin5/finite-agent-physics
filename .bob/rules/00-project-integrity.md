# Project integrity

- Treat every benchmark claim as unverified until a committed runner reproduces it.
- Never weaken a deadline, quality floor, permission, provenance obligation, or budget silently.
- Deterministic code owns authorization, feasibility, resource accounting, and pass/fail decisions.
- LLM-generated workflow graphs are untrusted inputs and must pass schema and semantic validation.
- Irreversible effects require an explicit approval and stable idempotency key.
- Tests must cover each new public invariant and at least one failure path.
- Update `docs/bob-build-log.md` only for the real current Bob session; never fabricate history.
- Preserve raw benchmark traces and identify simulated, replayed, and live behavior explicitly.
